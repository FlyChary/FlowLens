## 二、补测评测配置（256 MB、自动单进程）

### 2.1 查询延迟随写入速率（0/3/5/8 万每秒、每档 120 s、每档新容器）

`tools/exp/m1_q21.py`（自 p2d3_query_probe.py 派生：容器不加 cpuset、三类查询、0 档不起
loadgen、窗内逐秒采工作集与降级级别）。每类查询 20 q/s，回放 topk 用随机 `at` + 随机
10~60 s 窗口。每档从日志核对前端数 0。

| 写入速率 | 实测写入 | topk_default p50/p95/p99 (ms) | stats_default p50/p95/p99 (ms) | topk_replay p50/p95/p99 (ms) | 最高降级 | 工作集峰值 (MiB) |
|---|---|---|---|---|---|---|
| 0（只查询） | 0 | 2.0 / 3.0 / **3.4** | 1.9 / 3.1 / **3.4** | 2.0 / 3.0 / **3.4** | 0 | 107.8 |
| 3 万/秒 | 35000 | 2.0 / 42.0 / **71.6** | 2.3 / 42.7 / **75.4** | 2.4 / 44.8 / **74.4** | 0 | 180.7 |
| 5 万/秒 | 57500 | 2.5 / 43.8 / **76.5** | 2.6 / 43.8 / **77.9** | 2.6 / 44.7 / **76.8** | 0 | 179.2 |
| 8 万/秒 | 80000 | 7.8 / 43.0 / **75.0** | 8.7 / 45.4 / **76.5** | 9.7 / 45.6 / **72.7** | 0 | 176.0 |

**在 256 MB 评测配置下，默认窗口查询（topk/stats）在写入速率每秒 3 万条以下 p99 < 50 ms**
（0 档 p99 3.4 ms；3 万/秒起 p99 71.6/75.4 ms，超过 50 ms 目标）。

判读：
- 单进程下三类查询（默认 topk、默认 stats、回放 topk）p99 同量级（~72-78 ms）——与 P2d-3
  八.5 的 256m 单进程补测（8 万/秒下 87.7/87.6/89.1/88.8 ms）同结论：无前端本地答，所有
  查询都排在同一事件循环的写入块之后。
- p50 始终 2~10 ms（查询计算本身快），p99 的尾由写入块（单进程 2000 条/块）+ 每秒 tick
  独占段（定稿+快照 ~85-130 ms，P2d-3 二.3 探针已测）决定；3 万→8 万/秒 p99 基本不变
  （71.6→75.0），与"尾不主要来自写入速率"一致（P2d-3 二.1 512 MB 同现象）。
- 120 s 窗内 0 级：工作集 120 s 内只涨到 ~180 MiB（未及填满 600 s 保留期），第 3 级线
  200.7 MiB 未触发；10 分钟级持续写入会进第 3 级（见 2.2 与 P2d-3 五.3）。
- 与 P2d-3 八.5（8 万/秒、80 q/s + 20 SSE）的 87.7 ms 相比，本表 8 万档 75.0 ms 略低：
  本实验无 SSE 负载（三类查询共 60 q/s vs 原 80 q/s + 20 SSE），查询排队更轻。

  （P2d-3 第四节）——差距来自单进程写路径容量，不是内存上限。

### 2.3 精度

`tools/experiments.py` S3 原压测模式（可存档），长尾 3 万/秒 × 300 s。结果
`results/m1/20261021_154153/S3/`（存档 8,990,000 条事件）。发送 9,000,000 /
接受 8,990,000（99.89%，L3 期间少量拒写）。工作集 start/peak/end =
66.1 / **201.7** / 142.2 MiB；**t ≈ 212 s 进 L3**（前段 102~144 s 有过 L1/L2 短刺）。
结束抽 **200 个已定稿 60 s 区间**与精确解比较，**200/200 valid**。

| 指标 | 本次（256m 单进程） | 参照 P2d-3 三（512m/3 前端） |
|---|---|---|
| Top-K url 召回 | **1.000**（200/200） | 1.000 |
| Top-K url 计数误差（均值 / 区间最大） | **0.086% / 0.789%** | 0.028% / 0.185% |
| Top-K user 召回 | **1.000** | 1.000 |
| Top-K user 计数误差（均值 / 区间最大） | **0.127% / 1.546%** | 0.042% / 0.231% |
| 真实值落 [lower, upper] | **199/200**（两维各 1 个区间越界） | 100%（两维） |
| 去重用户数（HLL）误差（均值 / 最大） | **0.985% / 1.641%** | 0.984% / 1.663% |
| p95 字节（DDSketch）误差（均值 / 最大） | **0.007% / 0.303%** | 0.097% / 0.303% |

判读：

- 与 512 MB/3 前端同口径：**召回 1.000、HLL/p95 误差一致**（HLL 0.985% vs 0.984%，
  p95 最大 0.303% 完全相同），写入路径口径不变。
- **唯一的越界区间是 86.2~146.2 s**（url 最大误差 0.160%、user 0.292%）：该区间
  内 timeline 实测出现过 **L2（102.2 s、sample_weight=4）与 L1（143.2/155.2/158.2 s）
  的瞬时采样**（每秒采样的级别序列里非 0 仅这几拍，其余 242 拍 0 级、53 拍 L3 在
  212 s 之后），采样档丢事件造成的计数偏低不在 [lower, upper] 误差界模型内——
  **这就是降级采样档的精度代价的直接证据**。256 MB 评测配置在持续写入进降级档
  期间，Top-K 计数误差会超出声明的误差界；L0（无降级）下与已提交版本一致
  （2.1 的 120 s 档全程 0 级、精度即 P2c/F1 口径）。
