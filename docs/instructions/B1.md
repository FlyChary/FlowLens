网络说明：用户在国内，直接访问 Docker Hub 与 PyPI 可能很慢或失败。
- 拉取基础镜像会自动走镜像加速，无需处理

- 不要在镜像里写死任何代理或国内源地址

## 二、调试接口：GET /debug/structure

用于控制台页面的"内部结构"视图（参考 docs/prototype/console.html）。

1. 只有设置环境变量 FLOWLENS_DEBUG=1 时才注册这个路由；未设置时访问返回 404（与其他不存在的路径一致）
2. 参数：by（url 或 user，默认 url）；可选 at 与 window，提供时额外返回该查询区间的拆分结果
3. 返回内容（全部为只读数据）：
   - now_ms、当前秒、ring.next、最新定稿秒、保留范围的起止
   - 活跃环：每个有数据的秒桶的秒号、事件数（url 维度 DDSketch 的总计数）、两个维度名单的当前长度与容量、缺席上界 u、前 3 个 key 及计数
   - 线段树（by 指定的维度）：每个已冻结节点的层号、起点、名单条数、缺席上界 u、事件数；第 0 层与带统计概要的节点可直接取事件数，其他节点按其覆盖范围内叶子的事件数求和；每一层构建中节点的层号、起点、已并入的秒数、候选数
   - 查询拆分（提供 at 与 window 时）：环内整秒、线段树节点列表、边缘秒及其比例。必须调用 engine._plan 或在它的基础上取得结果，不能另写一套划分逻辑，否则页面展示的拆分可能与真实查询不一致
4. 性能：在满载窗口（两个维度名单都写满、线段树有完整 10 分钟历史）下，单次调用的耗时与响应体大小写进汇报，目标是 5 毫秒以内
5. 测试（tests/e2e/test_debug.py）：未开启时返回 404；开启后字段齐全；带 at 与 window 时，返回的拆分与 engine._plan 的结果一致；节点的事件数之和与对应区间叶子的事件数之和一致
