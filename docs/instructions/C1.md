## 一、内存账本工具：tools/mem_report.py

1. 在进程内构造满载状态：用 FakeClock 驱动一个 Engine，按 tools/flowgen.py 的分布生成事件，以模拟时间推进至少 11 分钟（线段树保留期填满，活跃环也满），每个模拟秒调用一次 engine.tick()。分布可选长尾、全随机两种，速率可配置（默认每秒 3 万条，足以让每个秒桶两个维度的名单写满）
2. 按组件统计实际占用，至少分出以下各项，每项给出对象个数与字节数：
   - 去重 Bloom filter
   - 活跃环中各秒桶的 Count-Min、名单（堆与索引表）、HLL、DDSketch
   - 线段树：各层累加器（Count-Min）、构建中的候选堆、已冻结的叶子与节点（名单数组、keys 列表）、HLL、DDSketch
   - 名单中 key 字符串本身占用的内存，单独列出，并统计"内容相同但对象不同"的重复份数与它们浪费的字节数
   - URL 归一化缓存、查询结果缓存、快照
3. 统计方法：numpy 数组用 nbytes；Python 对象用一个按对象 id 去重的深度遍历（gc.get_referents），同一个对象只计一次，并能按"属于哪个组件"归类。用 tracemalloc 的总量和进程常驻内存做交叉核对，报告无法归类的剩余部分
4. 写入路径的峰值：模拟一个解压后 4 MB 的请求从解析到写入的过程，用 tracemalloc 记录峰值增量
5. 输出一张 Markdown 表格（组件、对象数、字节数、占比），以及与 docs/DESIGN.md 第 5 节估算的逐项对比

## 二、评估节省方案（只分析，不实施）

对下列方案，在同样的满载状态下实际测算能省多少内存、对写入耗时有多大影响（可以在工具内对数据结构做"假设性"改动后重新统计，但不得修改 flowlens/ 下的代码）：
1. 字符串驻留：同一个 key 在各秒桶、叶子、节点中共享同一个字符串对象。分别测算在写入端驻留（引擎写入秒桶之前替换为驻留表中的对象，不需要修改冻结模块）能省多少；驻留表本身的开销；在全随机流量下（key 几乎都不重复）驻留表的上限应设多少才不会反而增加内存
2. 叶子与节点的 HLL 精度从 p=14 降到 p=12
3. 去重 Bloom filter 的位数减半时，误判率变为多少
4. 秒桶名单容量从 512 降到 256 时，对 Top-K 召回的影响（用 tools/exact.py 对比一个固定区间）
