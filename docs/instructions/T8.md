# T8：过载降级

不得修改冻结的基础模块（包括 ring.py、segtree.py）。设计依据是 docs/DESIGN.md 的 §3.6，下面写明了与设计文档不同的地方。

## 一、降级控制器（新建 flowlens/degrade.py）

纯逻辑，不依赖 aiohttp，便于单测。

1. 输入（每秒更新一次）：
   - occupancy：写入在途预留的占用率（Admission.occupancy，按解压后字节）
   - tick_lag_ms：Ticker 最近一拍相对预定时刻的延迟（last_tick_delay_ms）
   - memory_bytes 与 memory_limit_bytes（memstat）；memory_limit_bytes 为 None 时按 256 MB 计算
2. 级别与阈值（进入 / 退出，退出阈值更低，形成滞回；当前级别取所有满足条件中最高的一级）：

   | 级别 | 进入条件 | 退出条件 |
   |---|---|---|
   | 1 | occupancy > 0.6 或 tick_lag_ms > 1000 | occupancy < 0.4 且 tick_lag_ms < 500 |
   | 2 | occupancy > 0.8 | occupancy < 0.5 |
   | 3 | memory_bytes > 上限 × 0.78 | memory_bytes < 上限 × 0.70 |
   | 4 | memory_bytes > 上限 × 0.90 | memory_bytes < 上限 × 0.82 |

   内存阈值按上限的比例计算，不写死 200 MB / 230 MB：评测容器的上限可以从 cgroup 读到，比例换算到 256 MB 正好是设计文档里的 200 MB / 230 MB。
3. 对外提供（只读属性）：level、degraded（level > 0）、sample_weight、replay_paused、sse_slowdown、tighten_budgets、reject_ingest，以及最近一次的输入值，供 /healthz 展示。
   - sample_weight：level ≥ 2 时为 2；occupancy > 0.95 时为 4；否则为 1。必须是整数（DDSketch 的计数是整数）
   - replay_paused、sse_slowdown：level ≥ 1
   - tighten_budgets：level ≥ 3
   - reject_ingest：level ≥ 4
4. 级别变化时用 logging 记录一行（旧级别、新级别、触发的输入值）。

## 二、各级动作的接入

控制器挂在 app 上（web.AppKey），由 Ticker 每拍结束后调用一次 update（或单独的每秒任务，你选一个并说明理由）。

1. 第 1 级（查询让路）：
   - 回放暂停：/v1/topk 中需要回放的查询（带 at、或 window 不是 60 秒、或 k 超过快照名单长度）和 /v1/stats 的非 60 秒窗口，返回 503 + Retry-After: 1。读快照的默认查询照常返回
   - SSE 降频：订阅组的最小重算间隔从 1 秒变为 5 秒（帧照常按 interval 推送，复用结果）
   - 判断放在 QueryService 和 StreamManager 内部（各自持有控制器的引用），不要在 handler 里写分散的判断
2. 第 2 级（带权采样）：
   - 在 engine.ingest 中：按 event_id 的哈希做确定性采样（同一事件重试时取舍一致），保留比例 1/sample_weight，保留的事件以权重 sample_weight 写入
   - 只对 Top-K 名单（DimBucket.hh）和 p95（url 维度的 DimBucket.stats 里的 DDSketch）采样；HLL（user 维度的 stats）和 event_id 去重始终全量
   - 实现方式：DimBucket.observe 会把名单和统计一起写入，而 ring.py 是冻结的。引擎改为分别调用 bucket.dims[d].hh.observe(...) 和 bucket.dims[d].stats.observe(...)：url 维度两者都用采样后的事件与权重；user 维度 hh 用采样后的事件与权重，stats 用全部事件（权重 1）。不采样时（sample_weight 为 1）走原来的 observe，保证正常路径的结果与现在完全一致
   - engine.ingest 的 weight 参数改为由控制器提供的 sample_weight
3. 第 3 级（收紧内存）：
   - Admission 的上限从 4 MB 降为 2 MB，RawBudget 从 8 MB 降为 4 MB（退出第 3 级时恢复）
   - 拒绝新的 SSE 订阅（503 + Retry-After），已有订阅保持
   - 清空 QueryService 的结果缓存和 URL 归一化缓存（model._norm_cache），只在进入第 3 级的那一刻清一次
   - 与设计文档的不同：§3.6 写的是"缩短历史保留"，但保留时长由冻结的 segtree.py 在构造时确定，无法动态调整。把这一条追加到 docs/DESIGN_TODO.md
4. 第 4 级（拒绝写入）：写入请求在读取请求体之前直接返回 503 + Retry-After: 1。因为还没有写入去重状态，调用方重试是安全的
5. 从不降级的部分：URL 归一化、event_id 去重、HLL 全量更新、/healthz

## 三、响应中标明降级

- /v1/topk、/v1/stats、SSE 帧的 degraded 字段改为控制器的真实状态（目前固定为 false）
- 采样生效时（sample_weight > 1），/v1/topk 和 SSE 帧额外带 sample_rate 字段（1 / sample_weight）。注意：采样期间返回的上下界不再是严格保证，在 docs/DESIGN_TODO.md 里追加一条说明
- /healthz 增加 degrade 字段：{level, sample_weight, occupancy, tick_lag_ms, memory_bytes, memory_limit_bytes}

## 四、测试

- 新建 tests/test_degrade.py：每一级的进入与退出；滞回区间内保持不变；多个条件同时满足时取最高级；sample_weight 随 occupancy 变化；内存上限为 None 时按 256 MB 计算
- 集成测试（可放在 tests/e2e/ 或 tests/test_engine.py）：用可注入的控制器把级别固定在某一级，验证：
  - 第 1 级：回放查询返回 503 + Retry-After，默认窗口查询照常返回；SSE 重算间隔变为 5 秒
  - 第 2 级：采样生效，Top-K 计数约为真实值（误差在统计范围内）；去重人数与不采样时完全相同（HLL 全量）；同一事件重试时取舍一致；响应带 degraded=true 和 sample_rate
  - 第 3 级：Admission 与 RawBudget 的上限降低，退出后恢复；新 SSE 订阅返回 503；两个缓存被清空
  - 第 4 级：写入返回 503，且之后用同一批事件重试能被正常接受、不被判为重复
  - level 为 0 时，所有行为与 T7b 完全一致（现有测试全部原样通过即可证明）
