# P2d-2：前端直接回答默认窗口查询，前端分块解析

本文件给出详细设计与参考代码。参考代码是骨架：接口、顺序、边界条件按它来；标了"需要确认"的地方以实际代码为准，并在汇报中说明。不需要重新通读代码库。

## 〇、目标与依据

P2c：512 MB、写入每秒 14 万条时，默认窗口 topk 的 p99 为 78 ms，20 万条时为 102 ms；p50 只有 2～13 ms。查询本身很快，慢在排队：所有请求都在引擎的事件循环里先来先服务。

P2d-1 之后，查询由前端转发给引擎，仍然要在引擎的事件循环里排队。本任务做三件事：
1. **快照广播**：引擎每次生成新快照后，立即通过写入通道把它发给所有前端
2. **前端直接回答默认窗口查询**：不带 at、window 为 60 秒的 /v1/topk 与 /v1/stats，由前端用本地的快照副本回答，不经过引擎。快照本来就是"每秒整体替换、只读不改"的，复制一份给前端是安全的；前端与引擎用同一个函数从快照生成响应，结果逐字节一致
3. **前端分块解析**：前端解析一个 5000 条的请求约 45 ms，期间无法回答查询。改为每 1000 条一块、块间让出事件循环，使前端单次阻塞约 10 ms

另外顺手处理 P2d-1 审查中的一处：FLOWLENS_TEST_MEM 只在 FLOWLENS_DEBUG=1 时生效。

规则同 P2d-1（不改冻结模块；对外 HTTP 语义不变；前端数为 0 时行为与单进程模式完全相同）。每完成一节就提交一次；结果追加进 docs/lanes/P2-notes.md 的新一节"P2d-2"。

## 一、从快照生成响应的纯函数（flowlens/query.py、flowlens/api/app.py）

现在"读快照 → 组装答案"的逻辑写在 QueryService.topk / stats 的默认分支里（query.py 第 102 行、第 143 行附近），"答案 → 响应字典"的逻辑一部分在 stream.py 的 topk_data，一部分直接写在 app.py 的 _stats 里。把它们提取成纯函数，引擎和前端都调用，保证两边结果相同。

```python
# flowlens/query.py（新增，模块级）
def is_snapshot_query(at_ms, window_ms: int, k: int | None, top_n: int) -> bool:
    """默认窗口查询：不带 at、window 为 60 秒；topk 时还要求 k 不超过快照保留的条数。"""
    return at_ms is None and window_ms == DEFAULT_WINDOW_MS and (k is None or k <= top_n)

def topk_from_snapshot(snap: "Snapshot", d: Dim, k: int, window_ms: int) -> TopKAnswer:
    return TopKAnswer(d, k, window_ms, snap.from_ms, snap.to_ms, False,
                      snap.tops[d][:k], snap.unseen_upper[d])

def stats_from_snapshot(snap: "Snapshot", window_ms: int) -> StatsAnswer:
    return StatsAnswer(window_ms, snap.from_ms, snap.to_ms, snap.distinct_users, snap.p95_bytes)
```

QueryService.topk / stats 的默认分支改为调用 is_snapshot_query 与这两个函数（行为不变）。

### 2.2 消息类型与广播器

```python
# flowlens/ipc.py
MSG_SNAPSHOT = 3   # 引擎 → 前端：最新快照

def pack_msg(mtype: int, obj) -> bytes:
    """序列化成一整帧（头 + 负载），用于一次序列化、发给多个连接。"""
    data = pickle.dumps(obj, protocol=5)
    return _HDR.pack(len(data), mtype) + data
```

```python
# flowlens/__main__.py（或新建 flowlens/hub.py）
class SnapshotHub:
    """引擎侧：维护各前端写入通道的 writer，把最新快照广播出去。
    只保留"最新一帧"：如果上一次广播还没发完又来了新快照，就丢弃旧的、只发最新的。"""
    def __init__(self):
        self._writers: set = set()
        self._latest: bytes | None = None   # 最新一帧（已序列化）
        self._pending: bytes | None = None  # 等待发送的帧
        self._task: asyncio.Task | None = None

    def add(self, writer) -> None:
        self._writers.add(writer)
        if self._latest is not None:
            writer.write(self._latest)       # 新连接的前端立即拿到当前快照

    def discard(self, writer) -> None:
        self._writers.discard(writer)

    def publish(self, snap) -> None:
        """Engine.on_snapshot 回调。同步执行：序列化一次，安排异步发送。"""
        frame = pack_msg(MSG_SNAPSHOT, snap)
        self._latest = self._pending = frame
        if self._task is None or self._task.done():
            self._task = asyncio.get_running_loop().create_task(self._flush())

    async def _flush(self) -> None:
        while self._pending is not None:
            frame, self._pending = self._pending, None
            ws = list(self._writers)
            for w in ws:
                try:
                    w.write(frame)
                except Exception:
                    self._writers.discard(w)
            await asyncio.gather(*(w.drain() for w in ws), return_exceptions=True)
```

为什么不需要锁：asyncio 是单线程的，send_msg 中写头与写负载之间没有 await，SnapshotHub 也是一次 write 写出整帧，所以 ACK 与快照帧在字节流中不会交错。在 P2-notes.md 中记下这一点。

接入：serve_front 在开始读取循环前调用 hub.add(writer)，退出时（finally）调用 hub.discard(writer)；前端模式下 engine.on_snapshot = 一个同时做"发布共享状态"与 hub.publish 的函数（见 2.3）。

### 2.3 前端回答查询还需要的共享状态

前端组装响应时，还要用到引擎的 degraded、sample_weight 与 memory_bytes。在 P2d-1 的 SharedState 中增加三个由引擎写入的值：

```python
self.degraded = ctx.Value("b", 0, lock=False)
self.sample_weight = ctx.Value("i", 1, lock=False)
self.mem_bytes = ctx.Value("q", 0, lock=False)
```

引擎在两处写入它们：
- 降级级别变化时（P2d-1 中写 shared.level 的同一个 on_change 里）立即写 degraded 与 sample_weight
- 每次快照回调时写一次全部三个（memory_bytes 用 app 的 memory_reader() 读到的值，与 _stats 用的是同一个读数来源）

```python
def make_on_snapshot(hub, shared, controller, memory_reader):
    def on_snapshot(snap):
        shared.degraded.value = 1 if controller.degraded else 0
        shared.sample_weight.value = controller.sample_weight
        shared.mem_bytes.value = memory_reader()[0]
        hub.publish(snap)
    return on_snapshot
```

需要确认：sample_weight 是否只在级别变化时改变。如果在同一级别内也会变化（例如按占用率在 2 与 4 之间切换），那么每次快照回调写一次就足够（最多晚 1 秒），在汇报中说明。

### 2.4 前端接收快照

```python
# flowlens/frontend.py：EngineConnection 的读取循环中增加一个分支
if mtype == MSG_SNAPSHOT:
    self.state.snapshot = msg
    self.state.snapshot_recv_ms = time.monotonic() * 1000
    continue
```

```python
class FrontState:
    """前端本地的只读副本。"""
    def __init__(self, shared):
        self.shared = shared
        self.snapshot = None
        self.snapshot_recv_ms = 0.0

    def fresh_snapshot(self):
        """快照存在且在最近 3 秒内收到，才用于回答；否则转发给引擎（由引擎决定）。"""
        if self.snapshot is None:
            return None
        if time.monotonic() * 1000 - self.snapshot_recv_ms > 3000:
            return None
        return self.snapshot
```

## 三、前端回答默认窗口查询（flowlens/frontend.py）

```python
from .api.params import QueryParams
from .api.stream import topk_data
from .api.app import stats_body
from .query import is_snapshot_query, topk_from_snapshot, stats_from_snapshot
from .config import Config
from .timewin import Clock

_TOP_N = Config().snapshot_top_n
_clock = Clock()

async def _front_topk(request: web.Request) -> web.StreamResponse:
    st = request.app[front_state_key]
    snap = st.fresh_snapshot()
    if snap is not None:
        # 与引擎的 _topk 相同的参数解析与校验：非法参数在这里就得到与引擎一致的 400
        qp = QueryParams.from_request(request, _clock.now_ms())
        if is_snapshot_query(qp.at_ms, qp.window_ms, qp.k, _TOP_N):
            ans = topk_from_snapshot(snap, qp.by, qp.k, qp.window_ms)
            sh = st.shared
            return _json_response(topk_data(ans, degraded=bool(sh.degraded.value),
                                            sample_weight=sh.sample_weight.value))
    return await _proxy(request)

async def _front_stats(request: web.Request) -> web.StreamResponse:
    st = request.app[front_state_key]
    snap = st.fresh_snapshot()
    if snap is not None:
        qp = QueryParams.from_request(request, _clock.now_ms(), need_k=False, need_by=False)
        if is_snapshot_query(qp.at_ms, qp.window_ms, None, _TOP_N):
            sh = st.shared
            return _json_response(stats_body(stats_from_snapshot(snap, qp.window_ms),
                                             sh.mem_bytes.value, bool(sh.degraded.value)))
    return await _proxy(request)
```

## 四、前端分块解析（flowlens/parse_pool.py、flowlens/frontend.py）

```python
# flowlens/parse_pool.py
FRONT_PARSE_CHUNK = 1000   # 前端每块解析的条数：一块约 10 ms，前端在块间回答查询

def parse_chunks(raw: bytes, chunk: int = FRONT_PARSE_CHUNK):
    """与 parse_body 结果相同，但逐块产出：load_array 一次，validate 与哈希按块进行。"""
    arr = load_array(raw)
    for i in range(0, max(len(arr), 1), chunk):
        part = arr[i:i + chunk]
        batch = validate(part)
        yield ParsedBatch(ts=batch.ts, nbytes=batch.nbytes,
                          h_id=key_hashes(batch.ids), h_url=key_hashes(batch.urls),
                          h_user=key_hashes(batch.users),
                          urls=batch.urls, users=batch.users, invalid=batch.invalid)

def concat_parsed(parts: list) -> ParsedBatch:
    if len(parts) == 1:
        return parts[0]
    return ParsedBatch(
        ts=np.concatenate([p.ts for p in parts]),
        nbytes=np.concatenate([p.nbytes for p in parts]),
        h_id=np.concatenate([p.h_id for p in parts]),
        h_url=np.concatenate([p.h_url for p in parts]),
        h_user=np.concatenate([p.h_user for p in parts]),
        urls=[u for p in parts for u in p.urls],
        users=[u for p in parts for u in p.users],
        invalid=sum(p.invalid for p in parts),
    )
```

```python
# flowlens/frontend.py：FrontIngestService.ingest 中把 parsed = parse_body(raw) 换成：
parts = []
for part in parse_chunks(raw):
    parts.append(part)
    await asyncio.sleep(0)          # 块间让出，前端在这里回答查询
parsed = concat_parsed(parts)
```

需要确认：空数组（0 条事件）时 parse_chunks 仍产出一个空块，concat_parsed 的结果与 parse_body 相同（range 的 max(len, 1) 就是为此）；NDJSON 中某行不是合法 JSON 时 load_array 放入的占位值会被 validate 计入 invalid，按块切分不改变计数。

测试（tests/test_parse_pool.py 或新文件）：长尾、全随机、含各种非法事件、空数组、NDJSON、单个对象等输入，concat_parsed(list(parse_chunks(raw, c))) 与 parse_body(raw) 的每个字段逐项相同，c 取 1、7、1000、10000。
