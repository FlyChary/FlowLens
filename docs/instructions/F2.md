## 二、README.md

按评测方第一次拿到代码时的阅读顺序重写，内容简洁准确：
1. 一句话说明服务做什么
2. 快速开始：docker build -t flowlens . 与 docker run --rm --memory=256m -p 8080:8080 flowlens（注明国内网络可加 --build-arg PIP_INDEX_URL=...，默认使用官方 PyPI）；没有 Docker 时用 ./run.sh
3. 接口一览：POST /v1/ingest、GET /v1/topk、GET /v1/topk/stream、GET /v1/stats、GET /healthz，各附一条 curl 示例与返回示例
4. 自测：python tools/selftest.py --url http://127.0.0.1:8080（18 个边界用例）；pytest 的运行方式
5. 文档索引：docs/DESIGN.md（设计文档）、AI_LOG.md（AI 使用记录）、docs/perf/（性能剖析报告）、docs/EXPERIMENTS_FORMAT.md 与 tools/experiments.py（如何复现实验）
6. 已知限制：单进程单核，实测吞吐与 20 万条/秒目标的差距（数字以设计文档为准，这里写"见设计文档第 7、8 节"即可）

## 三、AI_LOG.md 开头加一段摘要

在文件最前面加"摘要"一节，不超过一页，挑出最有代表性的 8～10 条，每条两三句话，分三类：
- AI 的方案被推翻或修正的例子（例如：Python 版改为单进程单写者；历史层用"堆加缺席上界"代替 Count-Min；写入预留必须先于去重；64 MB 的请求上限在实测后改为 4 MB；内存读数从 memory.current 改为工作集）
- AI 犯的错被发现的例子（例如：numpy 定长字符串吞掉末尾的空字符；Windows 上内存读数恒为 0 导致问题只在 Linux 上暴露；打包配置漏掉 flowlens.api；对比函数把空结果算作召回 100%）
- 用实测推翻估算的例子（例如：C1 账本与容器实测相差 90 MB，C2 查明是 glibc 碎片与并发叠加，固定大块分配阈值后峰值下降约 58 MiB）
每条都要与正文中的记录一致，不要写正文里没有的内容。摘要末尾注明"以上由 AI 根据正文整理，已由本人核对"，提醒用户核对。
